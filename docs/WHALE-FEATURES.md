# 挂件（dsh-whale-widget）功能盘点与迁移到 dsh-pet 的评估

> 目的：dsh-whale-widget（页面内余额记账挂件）准备卸载，把其中值得保留的能力逐步迁进 dsh-pet（桌宠）。
> 本文按「功能 → 挂件现在怎么实现 → 迁移价值 → 迁移难度 → 是否依赖 DSH」盘点，并给出优先级建议。
> 状态时间：2026-11-18；挂件版本 0.4.2 + 本地补丁（MiniMax 周额度占位符）。

## 0. 两个项目的结构差异（先看这个，决定迁移方式）

| | dsh-whale-widget | dsh-pet |
|---|---|---|
| 形态 | DSH 页面右下角 DOM 浮层（单文件 ~22k 行前端 + 宿主 28 条路由） | 桌宠：浏览器 overlay + 独立 Electron 透明小窗（同一份 shared 渲染） |
| 数据层 | 宿主侧自有记账内核（`.dshw-usage.json`）+ 自带 34 个厂商模板 + 额度接口 | 宿主侧余额 provider 体系（window/money/points/custom 四种形态）+ 会话事件 |
| 气泡 | 模块化编辑器：任意行/列、文本/图片/随机语句/金额/额度占位符、逐模块样式 | 固定行模型（`BalanceBubbleRow`：label/sub/tier/quota/usage），由 shared 计算、两端渲染 |
| 角色/音效 | 自定义角色图库 + 音效组 + 泡泡图库 | 动画资产（webm）+ 角色/动作库 + 语音/碎碎念 |
| 独立性 | 必须跑在 DSH 宿主里 | 有独立模式（standalone，不依赖 DSH），但余额/工作状态仍依赖 DSH（见 §5） |

**结论**：挂件的「数据/记账/额度」值得迁；「页面 DOM 浮层 + 模块化气泡编辑器」不建议整套搬，用 dsh-pet 的固定行 + 新字段/新页扩展更划算。

## 1. 余额与额度

| 功能 | 挂件实现 | 迁移价值 | 难度 | 依赖 DSH |
|---|---|---|---|---|
| DeepSeek 余额 | API key 或 DSH 账号登录态 | 高（已有 money 形态） | 已具备 | 账号态需要 DSH |
| 多厂商模板（34 个） | 模板表：接口/字段路径/币种/凭据名 | 中：按需选 3~5 家即可 | 低（照 `BalanceProvider` 逐个加） | 否（key 从 DSH 凭据取，DSH 模式下） |
| 订阅额度接口（智谱/Kimi/MiniMax/OpenCode Go） | `kind:'quota'`：窗口已用% + 重置 | **高**（MiniMax 5h/周已实现） | 低 | 否 |
| MiniMax 周额度（本地补丁） | `weeklyRemainPct` + `weeklyResetAtMs`，占位符 `{plan_weekly*}` | **已完成**（pet 侧 windows+remaining 口径） | 已完成 | 否 |
| 余额校正 / 充值单独记账 | 余额上升记为充值、下拉「待核对调整」 | 中 | 中 | 否 |
| 余额预警（低于阈值弹提醒） | 气泡提醒 | 高 | 低 | 否 |
| 今日预算提醒 | 达阈值弹提醒 | 中 | 低 | 否 |

## 2. 记账

| 功能 | 挂件实现 | 迁移价值 | 难度 | 依赖 DSH |
|---|---|---|---|---|
| 今日已用（余额差） | 观测余额下降累计、跨天归档 | **高（pet 已实现：spend.json）** | 已完成 | 否（账号态需要 DSH） |
| 每轮对话消耗（真实 token × 峰谷价） | 监听 `session/event.assistant/message` 的 usage，按价目表结算，弹泡泡 | **高**（pet 也监听事件，可复用） | 中（价目表 + 事件聚合 + 落盘） | 是（需要 DSH 会话事件；独立模式不可用） |
| 峰谷定价（工作日 9-12/14-18 高峰，周末谷价，2026-08-23 起） | 内置价目表 + 节假日表 | 高（价目表照抄即可） | 低 | 否（是纯规则） |
| 用量记录窗口（今日/近7天/全部、模型占比、逐条明细、模型名友好标注） | 面板 + 账本 | 中（做设置页/气泡摘要先够用） | 中高 | 否（数据本地） |
| 账本保留/归档（明细 90 天/2 万条，逐日 365 天） | 账本归档文件 | 低~中 | 低 | 否 |
| 多厂商「今日已用」估算（无余额接口时按会话 token） | 事件归属 matchIds | 低 | 中 | 是 |
| Codex 本地会话统计（读 ~/.codex/sessions） | 解析 rollout JSONL | 低（当前不用 Codex 可跳过） | 中 | 否 |
| 记账分本（按 key 指纹）与余额校正 | 账本 books | 低（个人用可简化） | 中 | 否 |

## 5. 独立模式（dsh-pet standalone）现状与差距

pet 有独立模式：`node lib/standalone.js`（或桌面/开机自启），**不需要 DSH**；
但它目前明确写着：`余额 / DSH 会话工作状态 / 系统通知 仍需要 DSH 宿主`。

要让「独立 pet 也能记账/看余额」，需要补：

1. **独立模式的余额 provider 选择**：standalone 设置页现在可在 DeepSeek 官方 / opencode Go / commandcode 里选（`src/standalone/services.ts`），加 MiniMax 只需在 `BUILTIN_SERVICES`/`KeyName`/设置页选项里加一项，并复用 `providers/minimax-coding.ts`。
2. **DeepSeek 账号态余额**：DSH 账号登录态的服务只有 DSH 有；独立模式只能走 `DEEPSEEK_API_KEY`（官方余额接口）。若不想建 key，就得让独立 pet 仅在 DSH 运行时借用宿主数据（需要新的「宿主桥」）。
3. **每轮消耗/工作状态**：依赖 DSH 会话事件，独立模式拿不到；要么保留 DSH 插件双跑（会重复桌宠），要么做「standalone 连接 DSH 宿主」的桥（一个可选连接，DSH 在时增强，不在时降级）。

## 6. 建议路线（按性价比）

**P0（已完成/马上做）**
- ✅ MiniMax 5h/周额度（`percentMode: remaining`）
- ✅ 今日已用（余额差）`spend.json`
- ✅ 余额 + 额度 + 今日已用同屏编排（余额→今日→最紧迫窗口→重置）
- 待做：独立模式的 MiniMax provider（让 pet 不依赖 DSH 也能看 MiniMax 额度）

**P1（值得做，纯规则/纯数据）**
- 峰谷价目表 + 峰谷倒计时（纯规则，独立模式可用）
- 每轮对话消耗（DSH 会话事件；仅插件模式可用）
- 余额预警 / 今日预算提醒（纯本地阈值）
- 气泡第 3 页：用量摘要（今日/近 7 天/模型占比；数据来自本地账本）

**P2（体验增强）**
- 四边吸附（自由坐标 + 贴边镜像；浏览器与桌面 helper 两端）
- 对话名/峰谷模块进气泡
- 音效事件（消耗/提问/授权）
- 自定义静态角色图（png/gif → 单帧 webm 兜底）

**P3（不建议迁移）**
- 模块化气泡编辑器整套（拖拽排版/模块库/逐模块样式）——工作量最大、与 pet 的固定行模型冲突
- Codex 本地会话统计（除非真的用 Codex）
- 多账本分本/复杂余额校正

## 7. 数据兼容

挂件数据都在 `$DSH_HOME`（默认 `~/.dsh`）：

| 文件 | 用途 | 迁移建议 |
|---|---|---|
| `.dshw-usage.json` | 记账账本（逐轮明细/逐日观测） | 可一次性导入 pet 的账本（字段映射：金额→cost、日期→北京日） |
| `.dshw-api.json` | 自定义厂商注册表（不含密钥） | 只取需要的厂商映射成 pet 的 provider 配置 |
| `.dshw-size.json` | 外观/音量/吸附 | 只参考吸附参数 |
| `.dshw-bubble.json` | 泡泡配置/模块库 | 只参考常用文案 |
| `.dshw-codex.json` | Codex 统计缓存 | 不需要 |
| `whale-roles/` `whale-audio/` `whale-bubble-imgs/` | 角色/音频/图片 | 角色图可转成 pet 的静态图素材 |

卸载挂件**不会**删这些文件；pet 迁移时可按需读取（注意：迁移完成后建议另存备份，再清理）。
